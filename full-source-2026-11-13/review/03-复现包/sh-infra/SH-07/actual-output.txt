== 1. 生成的 503 server 里有那些放行/排除指令？==
   allow        不存在
   deny         不存在
   geo          不存在
   map          不存在
   satisfy      不存在
   auth_request 不存在
   ACME 例外   2 处（仅 /.well-known/acme-challenge/ 放行）

[+] 结论：503 规则对**所有** $NAMES 的站点都是 return 503，
    除了 ACME 挑战路径，没有任何 HTTP 层的放行（无管理 IP、无健康检查路径、无面板域名例外）。

== 2. 唯一的“排除项”：命名约定 ddos.* ==
   ddos-mode.sh:10 片段: ... grep -v '^ddos\.' ...
   => 只要 server_name 以 'ddos.' 开头就被排除，与“是不是管理面板”无关；
      反之，管理面板叫别的名字就不会被排除。

== 3. 用一组常见 vhost 名做推演：谁会 503、谁被排除 ==
   - 控制台域名就是 ddos.lzj2012.top
     进入 503 名单: chat.lzj2012.top lzj2012.top mc.lzj2012.top
     被排除:       ddos.lzj2012.top
   - 控制台叫 panel.lzj2012.top（不是 ddos.*）
     进入 503 名单: chat.lzj2012.top lzj2012.top mc.lzj2012.top panel.lzj2012.top
     被排除:       （无）
     <== 管理面 503：面板无法访问 -> 只能 SSH 或等 10 分钟自动退出
   - 控制台叫 logview.lzj2012.top

     被排除:       （无）
     <== 管理面 503：面板无法访问 -> 只能 SSH 或等 10 分钟自动退出

   注：真实站点集合无法确认（`etc/nginx/sites-enabled/ddos` 未交付），
       因此“到底哪个域名被排除”属于审查盲区。

== 5. 自锁评估 ==
   可恢复路径 1：SSH 登录后 `/usr/local/sbin/ddos-mode.sh off`（需要 root 权限）。
   可恢复路径 2：ddos-monitor 判定带宽回落并连续 10 分钟正常 -> 自动 mode_off。
                 该路径依赖 status.json 持续写入且 nginx -t 能通过（见 SH-02/SH-12）。
   不可恢复情形：sshd 之外的运维入口（面板/API）全部 503，且自动退出被 SH-02 的
                 标志/回滚缺陷卡死 -> 只能 SSH。
