== 2. 为什么这是 root 权限问题 ==
   - /tmp 带 sticky bit：任何本地用户都可以在“文件名不存在”时创建它
     （可以创建符号链接，但不能删除/替换 root 已创建的文件）；
   - 第一次成功抢注后，root 的 `>` 会打开该链接指向的目标并**截断**它，
     `>>` 继续追加 nginx -t 的输出 —— 链接一直存在，所以每次执行都会重复；
   - 也就是说：ddos-mode.sh 每次上线/运维执行，都会写一次攻击者指定的文件。

   用 Python 复刻“打开路径=跟随链接”的语义（模型，不实际创建链接）：
     open('/tmp/ddos-nginx-test.log','w')  ==  open(<link target>,'w')  -> 截断 target
   注意截断内容的可控性有限（内容 = nginx -t 的错误文本），因此主要是：
     * 破坏任意 root 文件（sshd_config / cron / ld.so.preload 等）-> 服务异常或提权链前置
     * 该日志文件 world-readable，泄露配置路径（信息量低）

   [判定] 可被本地用户预置链接 + root 固定路径覆盖 = 成立
