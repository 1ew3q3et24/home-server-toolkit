== 1. 状态映射矩阵（service 类型 + 声明了 port）==
   场景                           active   port_open  state      是否合理
   服务 active 且端口正常              active   True       良好         合理
   服务 active 但端口不通（进程僵死/未监听）    active   False      正常         不合理：应为异常
     <== 缺陷：端口不通却标 '正常'，面板上看不出服务实际不可用
   服务 failed                    failed   False      异常         合理
   服务 inactive（被停）              inactive False      停止         合理（但面板不一定告警）
   服务 activating（启动中）           activating False      异常         偏严：被标异常
   未知状态                         reloading-x False      异常         偏严

== 2. 端口探测本身的局限（第17-22行）==
   - 只连 127.0.0.1 的 TCP：服务绑在别的地址/只监听 IPv6 时会误判；
   - 只验证 TCP 三次握手：进程在听但业务已坏（DB 连不上、返回 500）仍算“通”；
   - timeout=1.5s：机器高负载时可能误报不通。
