== 1. “最多 10 分钟” vs 实际上限 ==
   循环次数=120（第127行），每轮最坏=探测5 s + sleep 5 s = 10 s
   最坏总耗时 = 1200 s = 20 分钟（注释写“最多 10 分钟”）
   => 注释与实际差 10 分钟；期间 failover 一直持锁，其它实例被跳过。

== 2. die 路径留下已启动的云端 MC ==
   failover.sh:146 `systemctl start mc`；failover.sh:146 `wait_for_port || die`
   die 只写日志/exit 1，不停 mc -> 若 DNS 仍指家里，云端 MC 会在后台运行
   （与 SH-03 的 state/DNS 分离叠加，就是双写窗口）。

== 3. 每次尝试都 drop_caches ==
   failover.sh 中 drop_caches 位置: [37]；mc-watchdog.sh:54 也有一处
   prep_mc_memory 在 force-cloud（第144行）与自动切云（第215行）各调一次，
   watchdog 每次 start 前再 drop 一次 -> 同一事件可能连续 drop 2~3 次。

== 4. 无 set -e：中间失败被忽略 ==
   failover.sh:4 = 'set -uo pipefail'（只有 -u -o pipefail，没有 -e）
   第21行 mkdir、第145行 touch、第113/116/148/156行 echo > 文件 都可能失败而不报。
