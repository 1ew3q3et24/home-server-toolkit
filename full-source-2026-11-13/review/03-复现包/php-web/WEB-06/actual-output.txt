=== 等价验证：三种输入 vs 真实 code 列值 ===
  [玩家按游戏提示粘贴链接] 输入='https://chat.lzj2012.top/v/ab12cd34ef56' -> $norm='2012123456', 格式校验=False
        -> 直接 fail('格式不对：请照抄游戏里给你的 8 位数字')，根本到不了 SQL
  [玩家手打 8 位码(旧格式)] 输入='1234-5678' -> $norm='12345678', 格式校验=True
        -> SQL 命中行: 无（找不到这个验证码）

=== 链接里的数字被“抠”出来后不可能等于 8 位码 ===
  https://chat.lzj2012.top/v/ab12cd34ef56  -> norm='2012123456' 长度=10 格式合格=False
  https://chat.lzj2012.top/v/001122334455  -> norm='2012001122334455' 长度=16 格式合格=False
  https://chat.lzj2012.top/v/ffffffffffff  -> norm='2012' 长度=4 格式合格=False

判定: 生产代码从不生成 8 位码（只生成 /v/<12hex> 链接），mcverify submit 仅认 8 位码；
      除非库中存在历史 8 位码行，否则 mcverify 的绑定向导必然报“找不到验证码”。
RESULT: 复现通过
