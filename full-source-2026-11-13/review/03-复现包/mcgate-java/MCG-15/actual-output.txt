== D. 判定分支模拟 ==
  普通已绑定玩家                        banned=False -> verify=false(放行)
  已绑定的被封禁账号                      banned=True  -> verify=false(放行)
  被封禁且未同意 TOS 的账号                banned=True  -> need_tos(冻结, 引导同意协议)

  被封禁账号与普通玩家判定完全相同 => 封禁对 MC 准入零影响。
  影响:
   - 运维'封了人'但对方继续进 MC 服(85% 直接进, 15% 拿码后因 403 无法提交, 重进再试) =>
     封禁的威慑力被显著削弱;
   - 同一玩家可换聊天账号, 但 MC 名绑定不变 => 换号后仍按'已绑定'放行?
     不: 绑定行 user_id 仍是旧账号, 新账号 submit 会被 409 挡住 => 反而锁死, 需人工处理。

== 修复建议 ==
  1) mc-api.php check 中 JOIN bans 判断: 若绑定用户存在有效 ban => 返回 {deny:true,reason}
  2) Backend.CheckResult 增加 boolean denied + String denyReason;
     Gate.onPreLogin(或 onJoin 的 kickTask 之前) 直接 kickPlayer(denyReason), 不进世界;
  3) 同时把 pending/ack 也按 ban 过滤, 避免被封账号的残留验证码触发解锁。

  check 分支无 ban 判断 + 插件无 deny 语义 => 静态确认(R2)。
