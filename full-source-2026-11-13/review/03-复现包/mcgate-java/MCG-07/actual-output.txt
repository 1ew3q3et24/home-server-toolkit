== 结论 ==
  * ack 与解锁不在同一个原子步骤里: ack 由异步线程无条件发出(Gate.java:179),
    解锁依赖主线程任务成功执行(Gate.java:164-178)。任何失败路径都会造成
    '后端认为已处理、客户端其实没解锁' => 玩家重进后被重新发码/再次冻结, 直到超时被踢。
  * mc-api.php:92 的 pending 只返回 submitted_at IS NOT NULL AND acked=0 的行,
    一旦被 ack 就不会再返回, 因此丢失不可自动恢复; 运维侧只能看到'玩家说验证了但没解锁'。
  * 多台 MC 服务器共用一个后端时更明显: A 服 ack 掉的名字, B 服永远收不到。
  丢失场景 = 3 / 4
